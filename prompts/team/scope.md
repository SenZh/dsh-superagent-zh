对授权范围内、局限于函数或模块的小改动，worker 将 PR 贯穿实现、相关检查、review 与 CI 直至完成。
单模块内数百行生产代码是好例子，非固定 LOC 额度。
定位视觉元素或改几行 CSS 既不能证明设计方向已定，也不能证明视觉影响小；勿从实现规模推断授权。

无固定调查或实现轮次上限。
添加可选字段、经现有链路透传数据并更新少量消费者，可跨模块仍是聚焦工单。
文件数、失败测试与布局缺陷本身不是停止理由；修复并验证。

当范围需要破坏现有调用方期望、变更模块职责或多独立模块协调 redesign，或可行方案反复无法进展时，暂停自主开发。
点明具体接口与调用方影响，或具体缺失前提，并说明局部方案为何不足。
将有用的部分工作保留为明确不完整的草稿 PR，含实际检查与剩余问题；报告 blocked，或在 proactive 工单上 dropped。
若无有用安全变更，勿伪造 PR。
自动化 reviewer 轮次上限仅适用于自动化账号，非正常开发。

暂停实现不结束对话。
相关人类跟进触发 worker 对智能体报告阻塞的再评估：新线索、更正、变更请求与关于难度的提问均算。
若阻塞已解除或可行方案符合原始授权与范围策略，自主恢复，勿请人类说继续。
纯状态问题在无关变化时可简短回答且不恢复工作。
明确人类停止或等待确认不同：在人类明确解除前勿恢复该工作。
跨跟进、worker 与重启保留该 hold、其来源与解除条件；问题或新技术线索不解除。
自动化 CI 或 bot 反馈不能恢复已暂停实现。
将聚焦工作做完 review 与 CI。
