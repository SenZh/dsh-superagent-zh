# 000 理念

dsh-superagent 既是一个框架，也是一种与智能体协作的方式。其核心原则是：

**尽可能少占用人的注意力，尽可能多产出价值。**

项目的每个部分都以「占用的注意力」来评判。一条消息、一次通知、一个问题、一项设置、面板上的一个元素、文档里的一段话，都会消耗某人的注意力；只有当它带来的价值大于这份消耗时，才应保留，否则应删除。

## 对智能体的要求

- **仅在被人请求时，或书面规则允许时行动。** 只有**直接对智能体**提出、且来自团队允许的人（在允许名单上，或在团队开放请求的会话中）的请求才算数。无人主动要求的工作需要团队写明的规则，并以**只记录智能体本会做什么、而不实际执行**的模式启动。
- **仅在必须有人行动或可以使用结果时发言。** 对请求确认一次并说明将要做什么；执行过程中保持安静；仅在结果就绪、需要决策或无法完成时再写。消息要短，且发回**提出请求的那条对话**。
- **一次只问一个具体问题，** 用结构化表单呈现，让问题能触达对应的人，而不是埋在一篇长报告里。
- **按影响范围决定停在哪里，而不是按已付出的努力。** 局部改动应推进到可审查的结果；需要设计决策的改动应带着清晰的问题停下。
- **如实汇报。** 草稿标明未完成，失败如实报告，不为回避提问而绕过限制。

## 对设计的要求

- **概念要少。** 设计只保留领域概念（例如 Source）及其实现（例如 GitHub、飞书）。业务需求应体现为其中某一概念的属性，或智能体遵循的 prompt，而不是为需求再发明一个概念。
- **设置要少。** 当几乎每支团队都适用同一取值时，用默认值代替设置。团队用文字描述的行为应写在 prompt 里，而不是做成配置项。
- **面板只展示需要人处理的事。** 优先列出等待人工的事项；一切正常时不占空间。
- **文档按序阅读。** 每篇编号文档只依赖其前面的文档，读者不必在未介绍过的概念上卡住。

## 责任

智能体会在你们团队日常可见的账号下评论、开 Pull Request、发消息。它发出的每条消息都会消耗同事的注意力，**运维者对此负责**。智能体能力越强，运维者对团队应尽的谨慎越多：

- **从窄范围起步。** 先用短允许名单，主动工作仅做记录；在「本会做什么」看起来正确后再放宽。
- **为降噪而调优。** 智能体太吵时，缩短并收紧 prompt，或暂停它；不要用更多消息去解释噪音。
- **不要用它刷量。** 批量 PR、群发消息、无意义忙活，对团队的消耗大于产出。
- **对发言内容负责。** 阅读它以你们名义发布的内容，错了就在 prompt 里纠正。

目标是**在对的时机给对的帮助，其他时候什么都不做**。
